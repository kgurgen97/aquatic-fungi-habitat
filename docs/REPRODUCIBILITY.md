# Reproducibility guide

## Environment

Use Python 3.11 or later and install `requirements.txt`. The scripts are single-file entry points at the repository root. `project_paths.py` resolves the project root from its own location.

To provide downloaded source data, set these environment variables to the relevant local directories:

| Variable | Expected input |
|---|---|
| `FUNAQUA_DATA_DIR` | FunAqua OTU tables and metadata |
| `NEON_DATA_DIR` | NEON processed taxonomy CSVs in `water/` and `benthic/` |
| `FUNGALTRAITS_DATA_DIR` | Fungal trait tables |
| `METAPR2_DATA_DIR` | Extracted metaPR2 data (including `asv.xlsx`) |

When unset, variables fall back to the original `~/research/datasets/...` layout. Do not commit access tokens or local copies of source data. The NEON processing workflow requires the correct product versions (DP1.20141.002 and DP1.20086.002) and an API token to acquire them.

## Results that can be checked without raw files

```bash
python verify_plan_hashes.py
python analysis_heterogeneity.py
python analysis_agreement_power.py
python tests/test_publication.py
```

These scripts use committed supplementary tables and reproduce S15–S19 and supplementary Figure S4. The analysis inputs S1 and S7 already reflect upstream filtering and rarefaction. This is a derived-results reproducibility check, not a complete raw-data reproduction.

## Full reprocessing

Retrieve the source datasets using the DOIs in README and the manuscript. Examine each relevant `*PLAN*.md` for fixed sample and parameter rules. The principal scripts include `analysis_primary.py`, `analysis_draw_stability.py`, `analysis_neon_validation.py`, `analysis_depth_ladder.py`, `analysis_sweep.py`, `analysis_benchmark2.py`, and `analysis_occupancy.py`.

Some scripts depend on intermediates generated by earlier scripts, including `results/presence_matrices.npz`, which is not redistributed due to size. The original analysis relied on downloaded source files and local preparation steps. Do not claim that a fresh, end-to-end raw-data reproduction has been demonstrated by the lightweight tests.

`python make_figures.py` generates the six numbered figures from derived results. `python analysis_agreement_power.py` generates supplementary Figure S4. `python make_supplementary.py` regenerates S1–S14 and supplementary Figures S1–S3 and may require the original source datasets; it should only be run once dependencies are available.

## Frozen plans and interpretation

Preregistration documents are kept in the repository root, and their recorded SHA-256 values are in `PLAN_HASHES.md`. Never edit a frozen plan to make a later result agree with it. Reports in `docs/analysis/` retain methods that failed or were superseded. Table S20 is a sensitivity calculation based on *assumed* intraclass correlations, not estimated site-level clustering.
